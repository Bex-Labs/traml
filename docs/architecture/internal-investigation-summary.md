# Internal investigation summary

The existing case workspace, review panels and submitted-review history contain an **Internal summary** link. This opens a lightweight preview in a separate tab without navigating away from local edits. The preview reads a new server snapshot; it never saves the workspace or sends review notes. The dashboard's existing unsaved-work protections remain in place.

The preview includes the canonical case reference, recorded ownership, current profile labels, subject reference if linked, saved draft revision/status/narrative/pins, all member alert and transaction references, complete managed workflow history with reviewer feedback, and linked internal package metadata. An absent saved draft is explicit. Alert evidence availability is an availability flag, not confirmation of independently verified ledger fields. Raw detection payloads, source documents, account balances and identity documents are not attached.

Choose **Print / Save as PDF** after reviewing the loaded snapshot, then select your browser's PDF destination. The CoreAML red document uses A4 pages, confidentiality markings, UTC snapshot/save times and page numbers in current Edge/Chrome. Browser print settings can affect the result; use default A4 sizing and turn off the browser's optional URL/date headers if desired. The PDF is a saved snapshot, not a digitally signed document or a regulatory filing receipt. Exporting creates no submission, approval, audit receipt, database record or server-side file. Protect downloaded copies as internal case material.

Only the case owner or an active same-bank head of compliance may read a summary. The server reuses the reviewed timeline authorization boundary and validates the complete member group and customer linkage. The RPC accepts one alert UUID and no client bank, actor or findings payload. PUBLIC and anonymous execution are revoked. All data comes from a stable statement snapshot. Complete history is capped at 500 entries, packages at 50, and the response at 2 MiB: exceeding a limit produces an explicit failure, never a silently incomplete document. Reads and context checks have deadlines. Print remains disabled until validation/rendering completes; refresh failures clear previous findings.

## Installation and verification

Apply the patch, run `node scripts/test-case-summary.cjs`, then `node scripts/apply-case-summary-local.cjs`. The installer targets only sentinel-aml on 55321/55322. It verifies the installed timeline body and staff helper, installs only the new read function, probes the existing marked cases/roles, and compares all existing application table hashes. No fixture setup or workflow action is performed.

Run `node scripts/verify-case-summary-local.cjs --headed` with the local app on 5520. It signs in through the real forms, opens the owner preview through the existing workspace, verifies the head's approved internal package and foreign-bank rejection, signs out on the server and checks unchanged table hashes. Network restrictions permit only the exact retained summary targets plus existing bounded reads/authentication; all workflow mutations remain blocked. The harness does not open an operating-system print dialog or write a PDF containing local case data.

`node scripts/test-case-summary-browser.cjs` is a separate optional native browser regression using actual preview markup/modules/CSS and a fictional SDK; it makes no Auth/database calls. On development systems Playwright is loaded from `.coreaml-test-tools/node_modules/playwright`; explicit executable/module environment overrides are available for isolated CI. Its optional PDF output is only synthetic test data. Multi-page printed output was rendered and visually checked in isolated Chromium. The local verification remains necessary because isolated tests do not establish live bank-policy correctness.
